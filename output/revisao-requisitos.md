# Revisão dos requisitos do AmpAI

Data: 12/10/2026. Código analisado: `cf64ea5ea7c0af5002585769936b982f334aed4f`.

Esta revisão compara os documentos locais com o modelo de dados, o catálogo, o editor, o inspector e os cálculos atuais. Não altera funcionalidades da aplicação. A classificação diferencia ausência confirmada, atendimento parcial, requisito já atendido e funcionalidade de fase posterior.

## Escopo que prevalece

As instruções do usuário substituem a arquitetura original: Next.js, cálculos no frontend, sem backend nesta fase e importação/exportação de projetos em `.json`. Portanto, a ausência de .NET, Rust, Python, APIs, banco de dados e sincronização em nuvem não é uma falha da entrega atual. A extensão `.ampai` foi substituída por `.json` por decisão explícita.

Exportar um projeto JSON e exportar a imagem de seu diagrama são recursos distintos. O JSON atende ao transporte dos dados, mas não entrega a exportação visual PDF/PNG solicitada no documento do MVP. Essa exportação pode ser implementada no navegador, mantendo o escopo atual.

## Documentação que precisa ser alinhada

- O MVP pede exportação visual PDF/PNG na Fase 1, mas o README atual declara PDF como não implementado nesta fase. O README documenta o estado do software; não cancela o requisito do MVP. É necessário concluir o recurso ou registrar uma decisão explícita de adiamento.
- Os PDFs de visão geral colocam parte do core administrativo na Fase 1; o guia do MVP concentra essa fase no workspace visual. A revisão usa o guia específico para o editor e as decisões explícitas do usuário para a arquitetura.
- O resumo do layout menciona a barra esquerda duas vezes, inclusive para propriedades. O esboço a mostra à direita, como na implementação. Isso é uma inconsistência textual da documentação, não uma funcionalidade ausente.
- O documento de explicação do unifilar contém apenas um link externo, sem texto de requisitos adicionais. O desenho AutoCAD e o PDF de simbologia foram usados como referências visuais, não como uma obrigação de reproduzir todos os dispositivos, relés e detalhes daquele projeto.

## Ordem sugerida de execução

1. Acrescentar classe de tensão dos cabos, incluindo persistência e importação compatível com JSONs anteriores.
2. Implementar a exportação visual PNG/PDF do diagrama no frontend.
3. Formalizar o modelo de painéis BT/MT e os papéis dos subelementos; definir o comportamento esperado do TIE antes de mudar a topologia.
4. Mapear e verificar os símbolos já utilizados contra a referência de simbologia.
5. Abrir backlog separado para memoriais, planilhas/CAD, harmônicas e motores normativos, respeitando as fases posteriores.
